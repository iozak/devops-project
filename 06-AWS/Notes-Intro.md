**Intro**
AWS evolved from an internal Amazon infrastructure project in 2002 into a globally available cloud platform by 2007. The introduction of services like EC2, S3, and SQS revolutionized how businesses build, deploy, and scale applications, making AWS a cornerstone of modern cloud computing.

AWS's global infrastructure is built from Regions, Availability Zones, and Edge Locations, allowing organizations to deploy applications that are highly available, fault tolerant, scalable, and performant. Choosing the right region, leveraging multiple AZs, and understanding edge locations are fundamental AWS concepts for building reliable cloud solutions.

When selecting an AWS region, consider these four key factors:
- Compliance (legal and regulatory requirements)
- Proximity (latency and user experience)
- Available Services (regional feature support)
- Pricing (cost optimization)

Availability Zones are isolated data centres within an AWS Region that provide redundancy and resilience. By distributing applications and resources across multiple AZs, organizations can protect against outages and ensure their services remain available even if an individual data centre fails.

Edge Locations are AWS's globally distributed Points of Presence that cache and deliver content closer to users. By reducing the distance data must travel, they lower latency, improve performance, and provide a faster, smoother experience for users worldwide.
